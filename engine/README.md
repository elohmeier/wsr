# Rust engine

`wsr-core` ports Wall Street Raider 9.85's PowerBASIC game logic independently of
the UI and operating system. `wsr-wasm` provides the browser session binding.
See the [project README](../README.md) to play or build the browser app.

All commands below run from the repository root.

## Layout

| Path | Purpose |
| --- | --- |
| [`wsr-core/src/state.rs`](wsr-core/src/state.rs) | Original globals, types, addresses and array bounds; generated by `tools/gen_state.py` using `tools/names.tsv`. |
| [`wsr-core/src/pb`](wsr-core/src/pb) | PowerBASIC numbers, strings, arrays, RNG, formatting and file I/O. |
| [`wsr-core/src/logic`](wsr-core/src/logic) | Game routines grouped by subsystem. |
| [`wsr-core/src/save.rs`](wsr-core/src/save.rs) | Original save-file reader and writer. |
| [`wsr-core/src/ui.rs`](wsr-core/src/ui.rs) | Host interface for dialogs, reports, time and file writes. |
| [`wsr-wasm/src`](wsr-wasm/src) | Session lifecycle, browser ABI and player-visible summaries. |

## Compatibility conventions

- Preserve original behavior, including bugs, by default. Keep repairs opt-in and
  document them in [BUGS.md](BUGS.md). Browser sessions enable the initial-share
  repair and safety checks around random searches, loading and saving.
- Identify ported routines with their original name and address, for example
  `/// Port of SaveGame (0x4857af)`. Mark missing work with `PORT-TODO(0xADDR)`.
- Preserve x87 extended precision and explicit SINGLE, DOUBLE and integer store
  boundaries. See [NUMBERS.md](NUMBERS.md) for representation, rounding and limits.
- Use Windows-1252 byte strings (`PbStr`) and byte-wise comparisons.
- Pass `g: &mut Globals` first, then `ui: &mut dyn Ui` and `rng: &mut pb::rng::Rng`
  when needed. RNG state is separate from `Globals`.

Port coverage does not establish complete behavioral parity. The public tests use
synthetic resources; optional differential tests execute original routines under
CPU emulation. [Campaign comparisons](CAMPAIGNS.md) check independent state, RNG,
UI and file trajectories after each command. A passing bounded run verifies only
the sequence it compared.

## Build and test

```sh
cargo test --manifest-path engine/Cargo.toml --workspace --locked
cargo build --manifest-path engine/Cargo.toml -p wsr-wasm \
  --target wasm32-unknown-unknown --release
```

The WASM build requires `rustup target add wasm32-unknown-unknown`. For a complete
web build, follow the [root quickstart](../README.md#run-locally).

## Original-engine comparisons

Extract your own 9.85 installer into the ignored `extracted/` directory, with
`WSR.EXE`, its DLLs and data files in `extracted/app/`. With `innoextract` installed:

```sh
innoextract --output-dir extracted wsr985.exe
mise install
mise run setup
mise run test-strict
```

`test-strict` generates `engine/target/owner-content.pack`, enables `original-tests`
and fails if the original cannot run or a seed filter selects no cases. Keep all
extracted files and generated resource packs private. `mise run test` runs public
tests through nextest; `mise run test-campaign` validates the campaign harness,
including original-engine integration. See [CAMPAIGNS.md](CAMPAIGNS.md) for runs
and replay instructions.

Emulator results are cached under `engine/target/emu-cache`. `WSR_SEED_THREADS`,
`WSR_EMU_CACHE_MB` and `WSR_EMU_CACHE_DIR` control seed workers, cache size and
location. The mise tasks use four test threads, four seed workers and a 20,000 MiB
cache limit.

## Host integration

A host thread represents one session. Install an immutable `Arc<ContentPack>` with
`content::install`; native tests can instead set `WSR_CONTENT_PACK`. The WASM
binding validates and installs content during installer import. Resource extraction
is described in the [browser guide](../web/README.md#runtime-resources).

The `Ui` trait is synchronous. The browser runs it in a Web Worker and waits for
modal replies through shared memory. Hosts supply `Ui::local_time` for ticker
deadlines and `Ui::write_file` for simulation saves, then persist `Env::files`
changes after each shell call in write order. Browser save confirmation follows
the storage acknowledgement; failed loads preserve the current session.

Hosts providing remarks and high scores retain `extensions::remarks::Remarks`
and `extensions::high_score::HighScores` across games and expose them through
`Ui::random_remark` and `Ui::high_score`.
